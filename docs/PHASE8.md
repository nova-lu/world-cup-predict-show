# Phase 8 — 淘汰赛阶段预测、晋级路径与旗帜视觉化体系

## 背景

2026 世界杯小组赛已持续推进，各小组的出线形势逐渐明朗。随着淘汰赛的临近，当前系统已具备以下基础能力：

- 小组赛积分榜 + 晋级概率榜（蒙特卡洛模拟 5000 次）
- 淘汰赛树形图一代（CSS Grid，基于模拟结果解析小组席位）
- 48 支球队元信息（含 emoji 国旗）
- 单场比赛预测（Elo/ML/Ensemble 三引擎）
- 赛程榜按阶段分类显示（GROUP_STAGE / LAST_32 / LAST_16 等）

但当前系统在淘汰赛阶段的功能还比较基础，存在以下关键短板：

| 方向 | 现有能力 | 短板 / 机遇 |
|------|---------|-------------|
| 淘汰赛视觉化 | CSS Grid 树形图（基础版） | 没有连线、没有队伍专属颜色、网格排版压缩严重 |
| 淘汰赛预测逻辑 | 直接套用小组赛的抽样逻辑 | 未考虑加时/点球、淘汰赛特有的压力因子 |
| 晋级路径 | 仅有分轮次概率 | 没有多步路径分析、对手分布预测 |
| 旗帜可视化 | 基础 emoji 国旗 | 无球队徽章、无球衣颜色、无球队专属元素 |
| 小组→淘汰过渡 | 手动解析小组席位 | 未自动识别已确定的出线球队、未显示第三名竞争势态 |

Phase 8 的核心目标是构建一套完整的淘汰赛体系——从小组到冠军，让用户能够直观地看到每一支球队的淘汰赛路径、每一场可能的对手、以及拓展到最终冠军的完整路径攻略。

Phase 8 将在现有基础上做四个方向的进化：
1. 淘汰赛嵌套预测引擎——专门针对淘汰赛场景的比赛结果预测（含加时/点球）
2. 晋级路径分析——每支球队的最佳路径、可能对手分布、分轮次晋级策略
3. 淘汰赛树可视化升级——连线引擎、球队彩色、旗帜徽章、自适应布局
4. 前端集成——淘汰赛仪表盘、小组→淘汰过渡、交互体验

### 设计原则
- **小组实时驱动**：淘汰赛对阵自动反映最新小组结果，无需手动更新

### 任务 8.1：淘汰赛预测引擎

目标：构建专门针对淘汰赛场景的比赛预测引擎，考虑加时、点球大战和淘汰赛特有的压力因子。

#### 背景
当前的 sampleMatch/predictMatch 逻辑在小组赛场景下正常工作，但在淘汰赛中存在以下问题：
- 淘汰赛没有平局——Elo 抽样需考虑加时和点球大战的影响
- 大赛压力因子——8强/半决赛/决赛的心理压力会影响球队发挥
- 未来淘汰赛的预测不应只显示胜平负概率，应包含加时胜/点球胜的分层概率
- 历史淘汰赛数据葡萄酒赛进球率低于小组赛，需当单独处理

#### 实施项

1. **淘汰赛加时/点球模拟**（server/services/knockoutEngine.js）
   - 新增 simulateKnockoutMatch(slugA, slugB, stage) 函数
   - 步骤 1：检测常规时间是否分出胜负（与现有 sampleMatch 一致）
   - 步骤 2：若常规时间平局，进入加时阶段：压缩对方进球率（防守为主）
   - 步骤 3：若加时仍平，进入点球大战：基于队友历史点球率抽样或随机模拟

2. **淘汰赛压力因子**（server/ml/features/knockout.js）
   - 淘汰赛阶段权重调整：QF/SF/Final 分别对应不同压力系数
   - 历史淘汰赛常规时间平局率（约 25-30%）统计
   - 点球大战历史胜率（无明显主客场优势）

3. **Elo 调整器**（server/services/elo-model.mjs 扩展）
   - 淘汰赛 K-因子从小组赛的 20 提高到 30-40（大赛对排名影响更大）
   - 常规时间结果与加时/点球结果分离记录

4. **淘汰赛压力因子配置**（server/ml/config.js 扩展）
   - STAGE_PRESSURE: { R32: 1.0, R16: 1.05, QF: 1.15, SF: 1.25, FINAL: 1.35 }
   - ET_BONUS: { attack: 0.85, defense: 1.10 }
   - PENALTY_WIN_RATE: { random: 0.5 }

#### 交付物
- server/services/knockoutEngine.js — 淘汰赛加时/点球模拟
- server/ml/features/knockout.js — 压力因子特征
- server/services/elo-model.mjs 扩展—淘汰赛 K-因子
- server/ml/config.js 扩展—淘汰赛配置

### 任务 8.2：小组→淘汰过渡管线

目标：将实时小组赛结果自动解析为淘汰赛对阵，包括第三名筛选。

#### 背景
2026 世界杯淘汰赛规则：
- 12 个小组前 2 名（共 24 支球队）直接进入 32 强
- 12 个小组的第 3 名中最佳的 8 支进入 32 强
- 32 支球队按类似现行规则配对：第一名 vs 第三名、第二名 vs 第二名
- 每轮单场淘汰汇合到下一轮。已完赛淘汰赛的胜利者自动填充后续对阵位置。

#### 实施项

1. **小组名次实时解析器**（server/services/groupResolver.js）
   - 从已完赛结果和小组积分榜自动解析每组前 3 名
   - 处理积分相同时的决胜规则：净胜球 > 进球 > 直接对战 > 红黄片
   - 2026 小组赛 48 场完赛后自动生成排名

2. **第三名筛选器**（server/services/thirdRankResolver.js）
   - 多组第三名比较逻辑（积分 > 净胜球 > 进球 > 平均积分）
   - 取最佳 8 个第三名进入淘汰赛
   - 需要考虑已确定和尚未确定的第三名位置（小组末完赛时）

3. **对阵生成器**（server/services/bracketBuilder.js）
   - 通过 32 支确定的小组名次和第三名生成淘汰赛树对阵
   - 对阵根据 FIFA 固定规则排列：
     - 1A vs 3C/3D/3F/3G/3H （已在 bracket.js 中定义）
     - 如果第三名还未确定，显示候选组
     - 如果第三名已确定，直接显示球队名称

4. **已完赛淘汰赛自动晋级**
   - 已完赛的淘汰赛，胜利者自动填充下一轮对阵位置
   - 结果来自已完赛比赛的实际比分，而非模拟
   - 如果未完赛，显示预测的最可能晋级球队

#### 交付物
- server/services/groupResolver.js — 小组名次解析器
- server/services/thirdRankResolver.js — 第三名筛选器
- server/services/bracketBuilder.js — 对阵生成器
- GET /api/knockout/qualifiers — 已确定的出线球队
- GET /api/knockout/third-rank — 第三名竞争势态
- GET /api/knockout/bracket — 确定性对阵（而非模拟）

### 任务 8.3：晋级路径分析

目标：针对每支球队解析其最可能的淘汰赛路径，显示每一轮比赛的对手分布和晋级概率。

#### 实施项

1. **路径分析器**（server/services/pathAnalyst.js）
   - 各轮次最可能对手分析：对每支球队，统计其在每轮淘汰赛最可能遇到的对手
   - “VS MVP”境物：指定球队在1/4决赛/半决赛最可能遇到哪支强队
   - 路径难度指数：每轮最可能对手的 Elo 平均 vs 该球队

2. **对手分布矩阵**（server/services/pathAnalyst.js）
   - 在蒙特卡洛模拟中统计每对淘汰赛的实际对阵授权
   - 生成“对手概率矩阵”：如 Brazil 在 R16 有 40% 遇到 Germany、30% 遇到 Netherlands
   - 显示在球队详情页和淘汰赛仪表盘中

3. **路径决策支持**
   - 淘汰赛对阵出来后，对每场淘汰赛显示两队在前一轮的对手
   - “如果 A 过关，下一轮相对于另一场的跑出者…”路径说明

#### 交付物
- server/services/pathAnalyst.js — 路径分析器
- GET /api/knockout/path/:slug — 单队路径分析
- GET /api/knockout/opponent-matrix — 对手分布矩阵

### 任务 8.4：淘汰赛树视觉化升级

目标：将现有的 CSS Grid 基础树形图升级为带连线、旗帜、自适应布局的专业级淘汰赛树。

#### 实施项

1. **SVG 连线引擎**（public/js/bracket-lines.js）
   - 在淘汰赛树的前后轮次之间画连线，显示晋级路径
   - 使用 SVG overlay 或 Canvas 在树形图上方绘制连线
   - 连线颜色根据该路径的晋级概率变化（绿色→黄色→红色）

2. **球队卡片统一组件**（更新 bracket.ejs）
   - 每张淘汰赛卡片包含：旗帜 + 球队名 + Elo 评分 + 晋级概率条
   - 已完赛卡片显示实际比分、胜利者绿色高亮
   - 未完赛卡片显示预测概率
   - 席位等待卡片显示候选组/候选球队

3. **自适应布局引擎**（更新 bracket.ejs 和 app.css）
   - 桌面版（>=1024px）：框架展开显示所有轮次+连线
   - 平板版（600-1024px）：显示当前轮次+相邻轮次，可水平滑动
   - 手机版（<600px）：显示所有轮次但缩小卡片，可水平滑动

4. **对阵详情层**
   - 点击淘汰赛卡片可跳转到 /match/:t1/:t2 预测详情页
   - 已完赛卡片包含比分链接

#### 交付物
- public/js/bracket-lines.js — SVG 连线引擎
- views/pages/bracket.ejs — 升级版淘汰赛树
- public/css/app.css — 新增淘汰赛树样式

### 任务 8.5：旗帜与球队可视化体系

目标：构建统一的旗帜、球衣颜色和球队徽章可视化体系，统一在淘汰赛树、比赛详情、小组积分榜中使用。

#### 背景
当前，48 支球队在 TEAM_INFO 中使用 emoji 国旗标识（如 🇧🇷）。这些 emoji 在桌面浏览器中显示正常，但在某些屏幕和操作系统上可能不完整或不一致。另外，球队没有专属的颜色标识。

#### 实施项

1. **SVG 旗帜下载系统**（scripts/download_flags.js）
   - 从公开 CDN（如 🏴󠁧󠁢󠁥󠁮󠁧󠁿/国家} .svg）下载 48 个国家的 SVG 旗帜
   - 存储在 public/images/flags/ 目录下
   - 备用方案：若 SVG 下载失败，回退到 emoji 显示

2. **球队颜色配置**（server/services/dataService.js 扩展）
   - 在 TEAM_INFO 中增加 color.primary、color.secondary、color.text字段
   - 例如：Brazil { primary: “#F7C622”, secondary: “#009739”, text: “#003F87” }
   - 当前先用简化配置，覆盖所有 48 支球队

3. **CSS 旗帜显示组件**（public/css/app.css 扩展）
   - .team-flag 类：支持 SVG 和 emoji 两种显示模式
   - .team-color-badge 类：显示球队专属颜色标识（小圆点/色块）
   - .team-name-colors 类：球队名称显示时使用主颜色
   - 输入格式支持 { flag: “/images/flags/brazil.svg”, color: “#009739” }

4. **旗帜在各页面的统一部署**
   - 淘汰赛树：每张卡片显示 SVG 旗帜 + 球队主色边框
   - 比赛详情页（match.ejs）：球队头像区显示大尺寸 SVG 旗帜
   - 小组积分榜：行首显示旗帜 + 颜色标识
   - 首页赛程卡片：旗帜替代 emoji
   - 各球队详情页（team-detail.ejs）：大旗帜展示

#### 交付物
- public/images/flags/*.svg — 48 个 SVG 旗帜文件
- scripts/download_flags.js — 旗帜下载脚本
- server/services/dataService.js 扩展—旗帜路径 + 颜色
- public/css/app.css 扩展—旗帜显示组件
- 各 EJS 模板更新—SVG 旗帜统一部署

## 四、推荐迭代节奏

由于 2026 世界杯已经开赛，小组赛将在 6 月底结束，淘汰赛将在 7 月初开始。因此迭代节奏应以“时间窗口”为导向，而非固定周数。

|阶段| 时间窗口 | 重点任务 |
|---|---------|---------|
| Ph1: 淘汰赛引擎核心 | 小组赛第 2-3 轮 | 8.2 过渡管线 + 8.1 淘汰引擎 |
| Ph2: 可视化升级 | 小组赛第 3 轮→R32前 | 8.4 树可视化 + 8.5 旗帜体系 |

## 六、发布与回滚策略

| 异常 | 自动措施 | 手动措施 |
|------|---------|---------|
| 小组名次解析失败 | 回退到模拟数据 | 修复 groupResolver 逻辑 |
| 淘汰赛树加载完全失败 | 显示“淘汰赛数据加载中”提示 | 切换回旧 bracket.ejs |
| SVG 旗帜不可用 | 回退到 emoji 显示 | 运行下载脚本或手动补充 |
| 路径分析 API 超时 | 返回基础路径信息 | 调整计算复杂度 |
| 前端页面样式破坏 | 隐藏新元素，显示旧版 | 调整 CSS 优先级 |

## 七、结论

Phase 8 的核心价值在于：

1. **小组到淘汰的自动过渡**：小组赛完赛后系统自动解析 48 支球队的名次，筛选最佳第三名，生成 32 强对阵。理论上在最后一场小组赛结束瞬间就能看到完整的淘汰赛树。

2. **淘汰赛特有的预测逻辑**：加时和点球大战的概率被形式化并融入预测，淘汰赛压力因子调整使得大赛场景下的预测更精确。

3. **路径可解释**：每支球队的最可能淘汰赛路径都可以看到，每一轮的对手分布都有概率支撑。

4. **视觉统一与专业化**：SVG 旗帜、球队专属颜色、连线引擎让淘汰赛树从“功能性工具”升级为“视觉产品”。

完成 Phase 8 后，系统将完整覆盖 2026 世界杯的全流程——从小组赛积分榜、晋级概率、单场预测，到淘汰赛树、路径分析、旗帜可视化——成为一个真正完整的世界杯数据看板。
