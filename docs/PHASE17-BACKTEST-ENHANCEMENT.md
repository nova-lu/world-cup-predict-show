## 2. 详细任务定义

### T1 — Elo 时间点快照系统 [P0]

**问题描述**: 当前 `predictor.js` 的 `getEloForTeam()` 使用 `elo-calibrated.json`（2026年7月的当前 Elo 评分）来预测 2002-2022 的历史比赛。这导致 Elo 回测准确率不可信——2002年的比赛使用了阿根廷2026年的实力评分。

**现有基础**: `server/ml/elo/update_elo_from_results.mjs` 已会生成 Elo manifests（保存到 `data/` 根目录），按时间点记录球队 Elo 评分。

**任务**:

| # | 交付物 | 说明 |
|---|--------|------|
| 1.1 | `server/ml/backtest/eloSnapshot.js` (新建) | `loadEloSnapshot(date)` 函数，查找最接近给定日期且早于该日期的 Elo manifest |
| 1.2 | 无快照回退算法 | 如果找不到对应日期的 manifest，从最新已知评分反向推演（Elo update 公式逆推） |
| 1.3 | 修改 `predictor.js` | `getEloForTeam()` 改为 `getEloForTeamAtDate(slug, date)`，从 snapshot 读取 |
| 1.4 | 验证 | 运行回测试验证 2002 年的 Elo 评分是否合理（如巴西 ≈ 巴西在2002年的真实 Elo） |

**验证**: 修改后 Elo 准确率在历史上应更稳定，不再出现"2026年评分预测2002年"的失真。

---

### T2 — ML 回测验证集隔离 [P0]

**问题描述**: 当前 ML 模型是在 2026 年训练的，训练集可能包含 2002-2022 的所有历史比赛结果。用同一模型"预测"它已经见过的比赛会导致验证集泄露，准确率虚假偏高（ML 52.0% vs Elo 37.8% 的差距很大可能源于此）。

**任务**:

| # | 交付物 | 说明 |
|---|--------|------|
| 2.1 | 时间序列交叉验证逻辑 | 对每届历史回测，训练一个"在该届比赛开始前"的模型版本（或记录该时间点的模型快照） |
| 2.2 | 或使用特征级隔离 | 最低限度：在 ML 特征中排除该比赛的直接结果信息，仅使用截止到比赛日期之前的数据 |
| 2.3 | 标注"可能存在数据泄露" | 在报告中标注 ML 指标的风险等级 |
| 2.4 | 可选：训练回测专用轻量模型 | 用 scikit-learn 训练一个轻量模型，严格按时间序列分割训练/测试集 |

**验证**: ML 历史回测准确率应接近 Elo（或略高 2-5%），而非当前显著高于 Elo 的水平。

---

### T3 — 2026 预测持久化机制 [P1]

**问题描述**: `data/backtest/predictions/` 目录存在但为空。2026 比赛的预测是"每次运行实时重新生成"而非"开赛前记录的快照"。随模型更新，历史预测会漂移。

**任务**:

| # | 交付物 | 说明 |
|---|--------|------|
| 3.1 | `server/ml/backtest/snapshotHelper.js` (新建) | `savePredictionSnapshot(match)` 函数，在比赛 FT 时触发 |
| 3.2 | 修改 `server/routes/matches.js` | 在赛程返回或 FT 状态检测时，将预测快照写入 `data/backtest/predictions/` |
| 3.3 | 持久化格式 | JSON Lines 格式（每行一条预测记录），按月份/轮次分文件 |
| 3.4 | 回测读取快照而非实时生成 | 修改 `collector.js` 的 `load2026Matches()`，优先从预测快照读取，无快照则回退到实时生成 |

**验证**: 2026 年比赛的回测结果应记录预测时间戳，不同时间运行回测同一场比赛结果一致。

---

### T4 — 赔率与 Polymarket 基线 [P1]

**问题描述**: `metrics.js` 的基线对比只有随机基线(33.3%)和 Always Home(43.5%)，缺少市场赔率基线。文档要求"赔率隐含概率的校准度"和"Polymarket 市场预测概率"。

**任务**:

| # | 交付物 | 说明 |
|---|--------|------|
| 4.1 | 竞彩网赔率基线 | 接入竞彩网历史赔率（`/api/odds/fusion/...`），计算赔率隐含概率的准确率/Brier |
| 4.2 | Polymarket 基线 | 从 Polymarket API 获取历史市场概率（需确认历史数据可用性） |
| 4.3 | `metrics.js` 新增基线计算 | `computeOddsBaseline(records)` 函数，返回共识赔率的准确率/Brier |
| 4.4 | 报告集成 | MD/CSV/JSON 报告中增加赔率基线行 |

**验证**: 报告中的基线对比表增加"赔率共识"和"Polymarket"行。

---

### T5 — 场景分析（大小球/BTTS/比分）[P1]

**问题描述**: 文档 §5.1-8 章要求 Over/Under 2.5、BTTS、比分精度、加时/点球 四类场景分析。现有 `inference/predictor.js` 的 `predictMatch()` 返回值已含 `overUnder` 和 `btts` 字段，但回测未读取和计算。

**任务**:

| # | 交付物 | 说明 |
|---|--------|------|
| 5.1 | `metrics.js` 新增 `computeOverUnderAccuracy()` | 将预测的 over/under 2.5 概率与实际总进球对比，计算准确率、Brier |
| 5.2 | `metrics.js` 新增 `computeBTTSAccuracy()` | 双方进球预测 vs 实际 |
| 5.3 | `metrics.js` 新增 `computeScoreAccuracy()` | xG 实际进球误差之外的比分精确命中率 |
| 5.4 | `metrics.js` 新增 `computeExtraTimeAccuracy()` | 淘汰赛加时/点球预测（如果数据可用） |
| 5.5 | `reporter.js` 增加场景分析章节 | MD 报告中新增第 8 章"场景分析" |

**验证**: 回测报告增加 Over/Under 命中率、BTTS 命中率指标行。

### T6 — 错误聚类与引擎优势分析 [P2]

**任务**:

| # | 交付物 | 说明 |
|---|--------|------|
| 6.1 | `metrics.js` 新增 `computeErrorClustering()` | 按 Elo 差梯度分组（悬殊/大热/势均力敌/大冷），计算每组的错误率 |
| 6.2 | `metrics.js` 新增 `computeEngineAdvantageAnalysis()` | 分析 ML vs Elo 在不同场景（淘汰赛/小组赛、Elo 差大小、置信度高低）下的胜负 |
| 6.3 | `reporter.js` 集成聚类结果 | MD 报告中增加聚类表格 |

**验证**: 报告中展示"Elo 差 0-50 时错误率 xx%"和"淘汰赛中 ML 比 Elo 好 xx%"。

## 3. 实施优先级与依赖关系

```
P0 ── Immediate
  ├── T1 (Elo 时间点快照)     ← 无依赖，独立
  └── T2 (ML 验证集隔离)      ← 无依赖，独立

P1 ── High
  ├── T3 (预测持久化)         ← 无依赖
  ├── T4 (赔率基线)           ← 依赖外部 API 可用性
  └── T5 (场景分析)           ← 无依赖，数据已存在于 predictor 输出中

P2 ── Normal
  ├── T6 (错误聚类)           ← 依赖 T1 修正后的数据可信
  ├── T7 (MD 报告增强)        ← 依赖 T5 + T6
  └── T8 (前端引擎对比)       ← 依赖 T6
```

**建议实施顺序**: T1 → T2 → T5 → T6 → T7 → T4 → T3 → T8

## 4. 验收 KPI

| 指标 | 目标值 | 验证方式 |
|------|--------|---------|
| Elo 时间点快照 | 所有 6 届历史世界杯前有可用的 Elo manifest | `loadEloSnapshot('2002-05-31')` 返回合理评分 |
| ML 验证隔离 | 历史回测准确率 <= 45%（去除泄露后的合理值） | 回测报告 ML 准确率下降至合理范围 |
| 预测持久化 | >= 80% 的 2026 已完赛比赛有预测快照 | `data/backtest/predictions/` 非空 |
| 赔率基线 | 报告中新增 >= 1 行外部基线 | 报告含"赔率共识"行 |
| 场景分析 | >= 3 类场景指标（OverUnder/BTTS/比分） | 报告含场景分析章节 |
| 错误聚类 | >= 3 个 Elo 差梯度分组 | 报告显示各分组错误率 |
| MD 报告章节 | >= 7 章 | 自动生成报告包含第6章+ |
| 前端对比视图 | 第4个 Tab 含 >= 2 种可视化 | 页面可操作 |
