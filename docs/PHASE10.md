# Phase 10 — 总览

> 本文档是 Phase 10 的总览，包含背景、全局目标、验收 KPI、迭代节奏与风险。
> 具体执行任务已拆分为 4 份详细文档，见下方链接。

## 背景

在 Phase 7-9 的基础上，系统已具备：
- 双引擎预测（ELO + ML）与融合框架
- 淘汰赛预测与路径分析能力
- Polymarket 接入与赔率融合接口
- 基础 CI/CD 与线上可部署能力

但当前业务进入"赛时高频更新期"，核心矛盾从"功能是否可用"转为"更新是否及时、信号是否充分、展示是否清晰"。

你提出的 5 个痛点非常关键：
1. 比分推荐需要方向一致，并控制为最多 3 条。
2. ELO 是否允许随最新赛果更新、更新幅度如何控制。
3. 博彩公司数据过少，不能仅 Bet365。
4. 需要规划接入国内竞彩网，体现赔率差异。
5. UI 需要更好看且更易交互。

## 全局目标 (Goals)

**G1 数据新鲜度**: 确保比赛结果更新后，训练特征、模型输入、线上预测在可控时延内同步。

**G2 ELO 可控更新**: 允许 ELO 根据最新赛果更新，但必须有幅度约束、回滚机制和审计记录。

**G3 赔率信号增强**: 从单源赔率升级为多公司对比，并为后续竞彩网接入预留标准接口。

**G4 推荐可解释**: 比分推荐控制为 Top 3 且与胜平负方向一致，降低推荐分裂感。

**G5 体验升级**: 在不破坏现有信息架构的前提下，提升视觉层级与交互效率（桌面 + 移动端）。

## 全局验收 KPI

| 指标 | 目标 | 关联任务 |
|------|------|---------|
| 数据滞后（results 到 features） | <= 10 分钟（手动触发模式） | A |
| ELO 更新稳定性 | 单场 delta <= 25，周级漂移可解释 | B |
| 赔率覆盖 | 每场 >= 3 家公司（可用时） | C |
| 比分推荐一致性 | Top3 与主方向一致率 >= 95% | D |
| 首屏关键信息可见性 | 桌面/移动均在首屏可见 | D |
| 比赛详情页加载时间 | <= 800ms（缓存命中） | D |

## 任务间依赖关系

```
A (数据新鲜度) - 独立 - 无下游依赖
B (ELO 更新)   - 独立 - 无下游依赖
C (赔率扩展)   - 独立 - D 的分歧 Tab 依赖其 API
D (UI 改版)    - 依赖 C - 分歧 Tab 调用 /api/odds/fusion/...
```

说明：
- 任务 A、B、C 互不依赖，可并行交付。
- 任务 C 和 D 有弱依赖：D 的分歧 Tab 调用 C 的 API。如果 C 尚未完成，D 的分歧 Tab 应显示 graceful degradation，不影响结论 Tab 和数据 Tab 的正常工作。

## 推荐迭代节奏（10 天）

**D1-D2: 任务 A + B 启动**
- 完成数据新鲜度检查脚本 (A)
- 固化 ELO 更新规则与参数边界，完成 update_elo 引擎 (B)

**D3-D4: 任务 C 启动**
- 完成多博彩公司抓取增强与 consensus (C)
- 完成融合链路读取 consensus (C)

**D5-D6: 任务 D 方向门控 + 任务 C 竞彩收尾**
- 完成 Top3 方向门控与服务端集成 (D)
- 完成竞彩离线适配器与映射表 (C)
- 加入方向门控回测统计（一致率、命中率）(D)

**D7-D8: 任务 D UI 改版（核心）**
- 完成比赛详情页三 Tab 重构 (D)
- 完成服务端预渲染逻辑 (D)

**D9-D10: 任务 D UI 收尾 + 联调**
- 完成客户端懒加载与 Tab 交互 (D)
- 桌面/移动端联调与性能检查 (D)
- ELO manifest + rollback 端到端验证 (B)

## 全局风险与回滚

| 风险 | 自动降级 | 手动措施 |
|------|---------|---------|
| 多赔率源部分不可用 | 保留可用公司 + 标记缺失 | 调整公司优先级 |
| ELO 更新后表现退化 | 回滚到上一个 elo manifest | 调低 K 或收紧单场上限 |
| 比分方向门控过严 | 不足 3 条时自动近邻补齐 | 放宽补齐阈值 |
| 竞彩网源不稳定 | 使用离线导入模式 | 保留接口不启用线上抓取 |

---

## 结论（不变）

Phase 10 的重点不是再加功能，而是把已有能力提升到赛时可运营状态：
- 数据更新可感知、可追踪、可回滚
- ELO 更新可执行且可解释
- 赔率从单源走向多源，逐步纳入国内数据
- 比分推荐从"多而散"变成"少而准、方向一致"
- 关键页面更清晰、更好看、更适合高频查看
